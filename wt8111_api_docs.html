📋 端点总览

端点方法用途需要参数
/stateGET己方载具完整飞行状态无
/indicatorsGET己方载具仪表数据无
/map_obj.jsonGET地图上所有对象（敌友单位、占领区等）无
/map_info.jsonGET地图坐标系参数无

💡 所有端点都是 http://localhost:8111 前缀，游戏运行时自动开启，无需认证。

1. /state — 己方载具飞行状态

GET
http://localhost:8111/state
⚠️ 实测发现：此端点仅在空战有效，陆战始终返回 {"valid": false}

3. /map_obj.json — 地图对象

GET
http://localhost:8111/map_obj.json
💡 实测：空战和陆战均可用。返回 JSON 数组，包含小地图上所有对象。

对象类型（type 字段）

type说明实测出现
ground_model地面单位（坦克等）✅ 陆战
aircraft飞机✅ 陆战（飞机出现时）
airfield机场空战
defending_point防御点—
bombing_point轰炸点—
capture_zone占领区✅ 陆战
respawn_base_fighter战斗机出生点✅ 陆战
respawn_base_bomber轰炸机出生点—
respawn_base_tank坦克出生点✅ 陆战

通用字段

字段类型说明
typestring对象类型
colorstring十六进制颜色码
color[]arrayRGB 数组
blinkint是否闪烁（0=否, 1=是）
iconstring图标名（Player=自己）
icon_bgstring背景图标
xfloat归一化 X 坐标（0~1）
yfloat归一化 Y 坐标（0~1）

飞机专用字段

字段类型说明
dxfloat航向向量 X 分量：cos(V)，范围 -1~1
dyfloat航向向量 Y 分量：sin(V)，范围 -1~1
航向角计算：angle = atan2(dy, dx) × (180/π)
模长验证：sqrt(dx² + dy²) = 1.0（归一化向量）
⚠️ dx/dy 仅 aircraft 类型有。ground_model 的 Player 对象也有 dx/dy，但意义可能不同。respawn_base 的 dx/dy 值如 300/-300，非方向向量。

机场专用字段（airfield）

字段类型说明
sx, syfloat跑道起点坐标
ex, eyfloat跑道终点坐标

图标类型（icon 值）

icon说明icon说明
Player玩家自己Fighter战斗机
Bomber轰炸机Assault攻击机
MediumTank中坦HeavyTank重坦
LightTank轻坦TankDestroyer坦歼
Tracked履带式Wheeled轮式
Airdefence防空单位defending_point防御点
bombing_point轰炸点capture_zone占领区

阵营颜色

颜色色值含义
🔵 蓝色#174DFF / #185AFF / #134AFF友军
🔴 红色#fa0C00 / #fa3200 / #e10B00敌军
🟡 黄色#faC81E玩家自己（实测）
🟢 绿色#67D756 / #24D921盟友（实测）

4. /map_info.json — 地图信息

GET
http://localhost:8111/map_info.json
http://localhost:8111/map.img

响应示例

{
  "grid_steps": [3250.0, 3250.0],     // 网格步长（米）
  "grid_zero": [-32768.0, 32768.0],  // 网格原点
  "grid_size": [1650.0, 1600.0],     // 网格大小（实测补充）
  "map_generation": 1,               // 地图版本
  "map_max": [32768.0, 32768.0],     // 地图最大坐标
  "map_min": [-32768.0, -32768.0],   // 地图最小坐标
  "hud_type": 1,                     // HUD类型（实测补充）
  "valid": true                      // 实测补充
}

坐标转换公式

归一化坐标(0~1) → 实际距离(米)：
实际X = x × (map_max[0] - map_min[0]) + map_min[0]
实际Y = y × (map_max[1] - map_min[1]) + map_min[1]

两点距离 = sqrt((x1-x2)² + (y1-y2)²) × map_max[0]
（简化版，假设 map_max[0] = map_max[1]）
💡 实测中 map_max=[4096, 4096]，归一化差 0.01 ≈ 41 米。

6. /hudmsg — HUD 消息（击杀/伤害事件）

GET
http://localhost:8111/hudmsg?lastEvt=0&lastDmg=0
⚠️ 需要查询参数，直接访问返回 400 Bad Request。

查询参数

参数类型说明
lastEvtint上次获取到的事件 ID，返回此 ID 之后的事件
lastDmgint上次获取到的伤害 ID，返回此 ID 之后的伤害
ID 从 0 开始递增，跨场不重置（第二局从上一局最后一个 ID 继续）。

响应示例

{
  "events": [],    // 事件列表（通常为空）
  "damage": [      // 伤害/击杀事件列表
    {
      "id": 161,
      "msg": "percusiones1r (Spitfire) set afire *shino_rs (Spitfire)",
      "sender": "",
      "enemy": false,
      "mode": ""
    },
    {
      "id": 162,
      "msg": "*shino_rs (Spitfire) has crashed.",
      "sender": "",
      "enemy": false,
      "mode": ""
    }
  ]
}

字段说明

字段类型说明
idint消息 ID
msgstring消息内容（击杀/起火/坠毁等）
senderstring发送者
enemybool是否敌方
modestring模式

📝 文档 vs 实测对比总结

文档未提及但实测发现的

发现说明
陆战 /state 不可用文档示例只展示了空战飞机数据，未说明陆战 valid=false
陆战 /indicators 字段完全不同飞机有 compass/altitude/g_meter，坦克有 army/crew/stabilizer/lws/ircm
map_obj 坐标是归一化 0~1文档未说明坐标系，实测确认是归一化值
map_info 有 grid_size 和 hud_type 字段文档未列出这两个字段
Player 对象颜色是黄色 #faC81E文档未列出玩家颜色
绿色 #67D756 是盟友文档未提及
陆战有 respawn_base_tank 类型文档未列出此类型
陆战有 capture_zone 类型文档未列出此类型

对空提前量计算相关数据可用性

需要的数据端点空战陆战
己方高度/state → H, m✅❌
己方垂直速度/state → Vy, m/s✅❌
己方航向/indicators → compass✅❌
己方速度/state → TAS/IAS✅✅ (/indicators → speed)
己方位置/state⚠️ 有经纬度❌ (仅 Player x/y)
敌机位置/map_obj → x, y✅✅ (2D归一化)
敌机航向/map_obj → dx, dy✅✅
敌机高度—❌ 无❌ 无
敌机速度—⚠️ 差分⚠️ 差分
最终结论：即使在空战中，8111 也无法提供敌机高度。/state 只提供己方高度，map_obj 只有 2D 坐标。这是 8111 接口的根本限制，不是模式问题。
